# Pokemo 배포 실행 순서

이 문서는 `진행상황.md` 기준으로 남은 배포 작업을 실제 실행 순서대로 정리한다.

## 1. 운영 DB 준비

1. AWS RDS MySQL 또는 운영 MySQL을 생성한다.
2. DB 이름, 사용자, 비밀번호를 정한다.
3. EC2에서 RDS 보안 그룹 접속을 허용한다.
4. 최초 빈 DB 배포 시 `.env`에 `JPA_DDL_AUTO=update`를 설정한다.
5. 테이블 생성 후 재배포부터는 `JPA_DDL_AUTO=validate`로 되돌린다.

AWS 리소스가 아직 없다면 다음 값으로 시작한다.

### RDS 권장 시작값

- Engine: MySQL 8.x
- Template: Free tier 또는 Dev/Test
- DB instance identifier: `pokemo-db`
- DB name: `pokemo`
- Master username: `pokemo`
- Public access: `No`
- Region: `ap-northeast-2`
- Security group inbound: EC2 보안 그룹에서 오는 MySQL `3306`만 허용
- Initial deployment: `.env`의 `JPA_DDL_AUTO=update`
- After first successful boot: `.env`의 `JPA_DDL_AUTO=validate`

RDS endpoint는 `.env`의 `DB_HOST`에 넣는다.

### EC2 권장 시작값

- AMI: Ubuntu Server 24.04 LTS 또는 Amazon Linux 2023
- Instance type: `t3.small` 이상 권장, 시연용은 `t2.micro`도 가능
- Storage: 20GB 이상
- Security group inbound: SSH `22`, HTTP `80`, HTTPS `443`
- SSH inbound는 가능하면 본인 IP만 허용
- RDS 보안 그룹은 EC2 보안 그룹에서만 접근 허용

EC2 생성 후 public IP 또는 도메인을 프론트 접속 주소로 사용한다.

## 2. EC2 서버 준비

EC2에 Docker와 Docker Compose plugin을 설치한 뒤 프로젝트를 배치한다.

```bash
docker --version
docker compose version
```

프로젝트 루트에서 `.env.example`을 복사해 실제 `.env`를 만든다.

```bash
cp .env.example .env
```

운영 배포에 최소로 필요한 값은 다음과 같다.

```env
COMPOSE_PROJECT_NAME=pokemo
DB_HOST=your-rds-endpoint.ap-northeast-2.rds.amazonaws.com
DB_PORT=3306
DB_NAME=pokemo
DB_USERNAME=pokemo
DB_PASSWORD=change-me
DB_SSL_MODE=VERIFY_IDENTITY
JPA_DDL_AUTO=update
JWT_SECRET=change-this-to-a-long-random-secret-at-least-32-bytes
CORS_ALLOWED_ORIGINS=https://your-domain.com
```

## 2-1. RDS TLS 강화 (VERIFY_IDENTITY)

운영 DB 연결은 `DB_SSL_MODE=VERIFY_IDENTITY`를 기본값으로 사용한다. 이 모드는 전송 구간 암호화에 더해 RDS 서버 인증서를 신뢰된 CA로 검증하므로 중간자 공격(MITM)을 방지한다. `REQUIRED`는 암호화만 하고 서버 신원을 검증하지 않으므로 운영에서는 사용하지 않는다.

AWS RDS 인증서는 Amazon RDS CA가 서명하며, 이 CA는 JVM 기본 truststore에 없다. 따라서 VERIFY_IDENTITY가 실제로 동작하려면 RDS CA 번들을 truststore로 만들어 연결에 전달해야 한다.

```bash
# 1) RDS 리전 CA 번들 다운로드 (ap-northeast-2 예시)
curl -O https://truststore.pki.rds.amazonaws.com/ap-northeast-2/ap-northeast-2-bundle.pem

# 2) JKS truststore로 가져오기 (비밀번호는 운영값으로 교체)
keytool -importcert -noprompt -alias rds-ca \
  -file ap-northeast-2-bundle.pem \
  -keystore certs/rds-truststore.jks \
  -storepass changeit
```

생성한 truststore를 backend 컨테이너에 마운트하고 `.env`에 연결 파라미터를 설정한다.

- `docker-compose.prod.yml`의 backend `volumes`에서 `- ./certs:/app/certs:ro` 주석을 해제한다.
- `.env`에 다음을 설정한다.

```env
DB_SSL_MODE=VERIFY_IDENTITY
DB_SSL_PARAMS=&trustCertificateKeyStoreUrl=file:/app/certs/rds-truststore.jks&trustCertificateKeyStorePassword=changeit
```

truststore 없이 VERIFY_IDENTITY로 기동하면 인증서 검증 실패로 DB 연결이 거부된다. CA 번들을 준비하기 전 임시로만 `DB_SSL_MODE=REQUIRED`로 내려서 기동할 수 있으나, 운영 확정 시에는 반드시 VERIFY_IDENTITY로 되돌린다.

## 3. 운영 compose 실행

외부 RDS를 사용하는 운영 compose 파일로 실행한다.

```bash
docker compose -f docker-compose.prod.yml --env-file .env config
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
```

상태를 확인한다.

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f backend
```

최초 실행 후 백엔드가 정상 기동하면 `.env`의 `JPA_DDL_AUTO`를 `validate`로 바꾸고 다시 배포한다.

```bash
docker compose -f docker-compose.prod.yml up -d --build backend
```

## 5. HTTPS 적용

도메인을 EC2 public IP로 연결한 뒤 Nginx 또는 Certbot으로 HTTPS를 적용한다.

현재 `docker-compose.prod.yml`은 호스트 Caddy가 80/443을 받고 프론트 컨테이너를 `127.0.0.1:8080:80`으로 프록시하는 구성을 기준으로 한다.

- EC2 보안 그룹 inbound: HTTP `80`, HTTPS `443` 허용
- DuckDNS 또는 운영 도메인의 A 레코드가 EC2 public IP를 가리키도록 설정
- Caddyfile 예시:

```caddy
pokemo.duckdns.org {
    reverse_proxy 127.0.0.1:8080
}
```

HTTPS 적용 후 `.env`의 `CORS_ALLOWED_ORIGINS`와 OAuth callback URL을 운영 도메인 기준으로 맞춘다.

## 7. CD 자동화

수동 배포가 1회 성공한 뒤 GitHub Actions CD를 사용한다. `.github/workflows/cd.yml`은 `main` push 후 CI가 성공하면 EC2에 SSH 접속해 `origin/main`으로 동기화하고 compose 재배포를 수행한다. 수동 실행도 `workflow_dispatch`로 가능하다.

GitHub repository settings의 Actions secrets에 다음 값을 등록한다.

| Secret | 예시 | 설명 |
| --- | --- | --- |
| `EC2_HOST` | `52.79.233.137` | EC2 public IP 또는 도메인 |
| `EC2_USER` | `ubuntu` | SSH 사용자 |
| `EC2_SSH_KEY` | `-----BEGIN OPENSSH PRIVATE KEY-----...` | EC2 접속 private key 전체 내용 |
| `EC2_PROJECT_DIR` | `/home/ubuntu/pokemo` | EC2의 프로젝트 경로 |
| `EC2_SSH_PORT` | `22` | 선택값. 비워두면 22 사용 |

CD 실행 전 EC2에는 다음 조건이 충족되어야 한다.

- `~/pokemo`가 GitHub 저장소 clone 상태여야 한다.
- 실제 운영 `.env`가 EC2 프로젝트 루트에 있어야 한다.
- Docker와 Docker Compose plugin이 설치되어 있어야 한다.
- Caddy HTTPS 구성 사용 시 `docker-compose.prod.yml`의 프론트 포트는 `127.0.0.1:8080:80`이어야 한다.
- EC2 보안 그룹에서 GitHub Actions runner가 SSH 접속할 수 있어야 한다. SSH source를 본인 IP로만 제한하면 CD가 실패할 수 있다.
